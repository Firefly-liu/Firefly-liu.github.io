视觉：YOLOv8 训练与 RKNN 部署全流程

智能车 视觉 YOLO RKNN · 约 11 分钟

视觉这块的链路很长：标注数据 → 训模型 → 导出 onnx → 转 rknn → 上车部署，任何一环版本不对都前功尽弃。而且训练阶段的报错"位置毫无逻辑"，一小点问题能报一堆不相关的错。这篇把完整流程和踩坑都列出来。

本页是两届队员接力的成果。按备赛日志的时间线：2025 年 9 月 19 日之前的内容来自上一届交接的日志（前届记录），之后是我自己的实践（我的实践）。

结论先行

能用 YOLOv8 就用 YOLOv8，但必须用专门适配了 RK 芯片的 ultralytics 分支。另外：pt → onnx 导出的模型，结构上必须有三个分支才对，对不上就别往下走。

二、环境与虚拟环境 前届记录我的实践

车上不能有虚拟环境（会带来各种依赖混乱），所以本机训练和车端运行要分开管理。

bash
# 自己电脑进入训练环境
conda activate yolov8

# Ubuntu 进入转换环境
conda activate rknn

# 车上进入推理环境
conda activate rknntest

# 退出环境
conda deactivate
Python 版本下限

至少 3.9。低于这个版本，后面会莫名其妙失败。

三、数据集：这是效果的上限 前届记录

模型结构决定下限，数据集决定上限。这一段是前届记录里最强调的部分。

拍照

先模拟各种环境对不同类别拍照：不同曝光、不同背景、不同颜色光、不同角度。一个类别拍得越"杂"，模型泛化越好。

标注

  • 手动标注，不要偷懒用自动标注的初稿；
  • 框不要标太大，贴着目标边缘即可；
  • 标完严格检查 txt 标签文件的类别序号，必须与训练用的类别列表顺序完全一致——这是最常见的低级错误。

增强

一张图大约能增强出 8 张。前届记录里把数据集从 1700 张扩充到 6500 张之后重新训练，效果有明显提升。

分辨率混用的隐患

前届的数据集有高分辨率、低分辨率两套，直接混合训练。识别效果不错，但留下了一个隐患：会出现两个置信度 9.0 以上的识别框（一大一小），在 NMS 几乎拉满的情况下，偶尔滤掉大框、偶尔滤掉小框。

四、训练 前届记录我的实践

训练用 train.py。下面是各参数的含义与我实际用的取值：

参数含义建议值
model预训练模型。可填上次中断训练的 last.pt 路径继续训练按需
data数据集 yaml 文件按需
epochs训练轮数数据集 ≥700 时 200 轮基本够
imgsz分辨率640（车上就是 640，再高没意义）
device训练硬件0 用 GPU，cpu 用 CPU
patience多少轮无改善就提前结束30
batch每批图像数16，也可填 -1 自动调整
盯住内存

我本机是 32G 内存，训练时内存爆了就直接不能训练。没有钞能力不要轻易开虚拟内存——虚拟内存有把系统搞崩的风险。

另外 pt 文件里 ReLU 和 SiLU 的取舍不强求，听说 ReLU 快一点，可以试。

五、pt → onnx 我的实践

千万不要用原版 ultralytics 导出，必须用 RK 改过的版本。导出命令：

powershell
$env:PYTHONPATH = "./"
python ./ultralytics/engine/exporter.py
导出后必须查模型结构

打开 netron.app，把 onnx 拖进去看。有三个分支才是对的（YOLOv5 和 YOLOv8 都一样）。对不上就重新导出，实在不行重装环境。

六、onnx → rknn 前届记录我的实践

bash
conda activate rknn
cd rknn_model_zoo-2.0.0/examples/yolov8/python
python convert.py 你的模型.onnx rk3588
版本必须对齐

rknn-toolkit2 与 rknn_model_zoo 要是同一版本。车上搭载的是 2.0.0 Beta，我就用这个版本。用 2.3.0 也能跑，但会报版本对不上的警告。
另外，如果 onnx 旁边还有 .onnx.data 文件，必须放在同一路径下。

输出头数量对照

yolov8.rknn 是 9 个输出头，yolov5.rknn 是 3 个。对不上就得从头开始，不能混用。

七、车端部署 我的实践

把上一步得到的 rknn 权重传到车上的 ucar_ws，放进 rknn-multi-threaded-yolov8/rknnModel 目录，然后改三个地方：

python
# main.py 约第 105 行：指定模型路径
modelPath = "./rknnModel/你的模型.rknn"

# func.py 约第 7 行：检测类别名称，顺序要与训练一致
CLASSES = ("类别1", "类别2", ...)

# func.py：类别数组与中心点数组，长度按你要检测的数量填
class_array  = [0.0] * 类别数量
center_array = [[0.0, 0.0]] * 需要输出坐标的数量
帧率门槛

运行 main.py 后确认帧率 ≥ 25fps 才能实际使用。低于这个数，车在运动中的检测会跟不上。

不要把 YOLOv5 的代码给 YOLOv8 用

输出头数量不一样，代码不通用。这是日志里在转换阶段浪费最多时间的一个坑。

八、踩坑总结 前届记录我的实践

环境

清华源没有 GPU 版 PyTorch

一键配环境的脚本能自动匹配适配的 PyTorch，但国内镜像源里只有 CPU 版。装 CUDA 时虽然向下兼容，也建议选你能支持的最新版，Beta 版别碰。

环境

unicodeescape 报错

报 syntaxerror: (unicode error) 'unicodeescape' codec can't decode bytes ... truncated \uxxxx escape 时，我的解法是先 pip uninstall ultralytics，再 pip install ultralytics。

部署

miniconda 不要装在根目录

装的时候记得改路径，放根目录会导致硬盘不足。

训练

虚拟环境很占内存

每次弄错都要新建环境，建议及时删掉不用的环境，并在 base 环境下用 conda clean -p 清理缓存。

部署

测好模型结构再去转

转换完成后再用 netron 看一眼结构，确认输出头数量正确。有报错就问，别硬猜。

九、一个意外的结论 我的实践

YOLOv8 也能识别文字

一开始我觉得 YOLOv8 识别不了文字，实际做下来完全没问题。我用手机拍照训练的数据，识别距离能到 130cm。后面有时间可以再补一些远距离样本。

但"用检测模型做文字识别"和"用专门的 OCR 做文字识别"是两条路。下一篇讲后者——把 OCR 从 CPU 搬到 NPU 上，帧率提升了一个数量级。
