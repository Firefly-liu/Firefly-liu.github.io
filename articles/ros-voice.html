语音交互：从离线命令词到在线识别

智能车 语音 ROS · 约 7 分钟

语音这一块是两届队员接力做出来的，中间经历过"识别能用但不播报"、"播报能用但唤醒不了"、"全都好了但官方突然改了发车方式"三个阶段。把可复用的部分整理在这里。

一、整体链路

语音系统最终分成四块，彼此通过 ROS 话题解耦：

输入

唤醒 + 命令词识别

离线命令词负责"听得见、听得出关键词"，是整个链路的触发源。

判断

关键词提取与业务判断

把识别结果做正则处理，提取出业务关键词，再决定发车、前往哪个导航点。

输出

语音合成 / 音频播报

两条路：离线 TTS 合成，或预先录好的 mp3 直接播放。

控制

与导航主程序通信

通过话题发布控制指令，主程序订阅后驱动车辆移动。

二、离线命令词识别 前届记录

离线识别 SDK 的目录结构里，真正需要动的只有几个文件。最关键的一点：离线资源 common.jet 是有有效期的（大约三个月），过期后必须去开放平台重新下载替换。

过期时的典型报错

如果语音突然全部失效，先看日志里有没有 build grammar error, errcode = 11212。是这个错，基本就是资源过期，直接换 common.jet。

替换与配置流程

步骤
1. 在开放平台创建应用，拿到 APPID 与 APPKey（离线命令词识别 + AIUI 平台）
2. 下载 SDK，解压后把 bin/msc/common.jet 复制出来
3. 用它替换 speech_command/config/AIUI/asr/common.jet
4. 修改 Global.h 里的 APPID 与 APPKey
5. 修改 speech_command/config/AIUI/cfg/aiui.cfg 里的路径
6. 重新编译
两个容易漏的点

第一，配置里除了 APPID，下面还有一个 APIKey 也要改，只改 APPID 是起不来的；第二，改完唤醒词要重新开一个终端才生效。

三、让 mp3 能播出来 前届记录

系统默认缺少 mp3 的解码支持，报错不一定明显，装一个包就好：

bash
sudo apt-get install libsox-fmt-mp3

四、离线语音合成（TTS） 我的实践

车上用的是 voice_system 里的 TTS 节点。改动点只有登录参数和资源路径。

cpp
// xcg_sub_tts.cpp
// 1) 语音文件生成目录与播放路径（文件名可改，但两处必须一致）
const char* fileName = "/home/ucar/Downloads/ucar_ws/src/voice_system/voice/xcg_voice.wav";
const char* playPath = "play /home/ucar/Downloads/ucar_ws/src/voice_system/voice/xcg_voice.wav";

// 2) 登录参数：把 APPID 换成你自己的
const char* login_params = "appid = 你的APPID, work_dir = .";

改完之后别忘了 TTS 自己的资源目录也要跟着换：

bash
# 语音合成资源目录
/home/ucar/Downloads/ucar_ws/src/speech_command/config/AIUI/tts/

# 编译
catkin_make

# 启动合成节点
rosrun voice_system xcg_sub_tts

# 手动测试
rostopic pub /xcg_tts_topic std_msgs/String "测试内容"

在 Python 里调用合成

把发布部分封装成一个函数，业务代码里只写一句话即可：

python
tts_publisher = rospy.Publisher('/xcg_tts_topic', String, queue_size=10)

def voice_make(command_content):
    msg = String()
    msg.data = command_content
    tts_publisher.publish(msg)
    rospy.loginfo("已发布: %s", command_content)

# 使用
voice_make("系统启动")
voice_make("我是文字{}我是文字".format(变量))

五、用现成音频播报 我的实践

如果不想走 TTS，也可以直接播 mp3。用 pydub 加载再播放，按编号或字符串找文件名：

python
def play_voice(number):
    if type(number) == str:
        audio = AudioSegment.from_file(str(number) + ".mp3")
    else:
        audio = AudioSegment.from_file(str(int(number)) + ".mp3")
    play(audio)

# 使用：play_voice(1) 播放 1.mp3
#      play_voice("系统启动") 播放 系统启动.mp3
音频文件放在同一目录

AudioSegment.from_file 用的是相对路径，音频文件必须和运行脚本在同一目录，或者写绝对路径。

六、从离线升级到在线识别 我的实践

后期官方把发车方式从"离线命令词"改成了在线识别，只能跟着改。思路是这样的：

关键难点：麦克风被占用

离线命令词识别会一直占着麦克风，没法同时给在线识别用。解决办法是绕过识别，直接采集音频——把麦克风能拿到的所有音频通过话题发出去，再由一个转发节点接收并提交给在线接口，拿到回复后做正则处理提取关键词，再发回控制话题。

python
# xunfei_Voice_get_online.py 里需要改的三个参数（换成你自己的）
APPID     = "你的APPID"
APISecret = "你的APISecret"
APIKey    = "你的APIKey"
在线接口的用量要盯着

WebAPI 是按服务量计的，跑比赛前务必确认剩余额度。额度用完的表现和"参数填错"很像，容易浪费时间。

七、多线程与节点存活 我的实践

接收语音指令的同时不能阻塞主流程，所以要用多线程。另外要分清 rospy.sleep() 和 rospy.spin()：

python
import threading

def 多线程函数名():
    t = threading.Thread(target=要一直运行的函数名)
    t.start()
    voice_make("语音系统等待中")

# rospy.sleep(1)   → 休眠，会释放 CPU 资源（可以当 delay 用）
# rospy.spin()     → 让节点保持活跃、持续接收消息，放在进程最后

八、错误码对照 前届记录我的实践

错误码含义处理方式
11212build grammar error离线资源过期，重新下载替换 common.jet
10407APPID 校验失败，APPID 与 MSC 库不匹配确认 APPID 与 SDK 属于同一个应用
22002文档里查不到的错误优先回退到上一份能跑的配置，逐项对比改动
回档是最有效的调试手段

语音模块涉及的文件多、生效条件隐晦。养成"每改通一步就存档"的习惯，出问题时用回档大法比逐行排查快得多。
